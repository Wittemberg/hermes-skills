# Adapting a skill written for another runtime

Skills vendored from another agent project rarely run as-is. Read the whole SKILL.md before installing, not just the frontmatter.

## Strip dependencies on the source project's tooling

Skills lifted from an app repo often instruct the agent to call that app's own MCP tools or internal functions — sometimes while explicitly forbidding the generic alternative ("do not use curl, always use `<app>_get_snapshot`"). Those tools do not exist in this Hermes instance, so the skill becomes an instruction to call nothing.

Rewrite the procedure around tools that are actually present (`curl`, `ssh`, `ffmpeg`, Python), and carry over the error-handling the removed tool was doing internally — size checks, content-type checks, retries. Say in the report that you made the substitution, and offer the alternative (run the upstream service and attach it as an MCP server) rather than deciding it for the user.

## De-escape embedded markdown

Docs generated by a JS/TS toolchain arrive with backslash-escaped backticks and literal `\\r\\n` sequences. Passed through verbatim, code blocks stop rendering and the agent reads escape noise as syntax. Unescape when converting the file, e.g. in Python replace the escaped backtick with a bare backtick before writing.

## Split body from depth

When upstream ships one long file mixing procedure with API trivia, put the always-needed operating rules and the common commands in SKILL.md and move firmware quirks, fallback cascades, and error tables to `references/<topic>.md`. Add one line in SKILL.md pointing at the reference and saying when to read it — otherwise it is never opened.

## Rewrite the description for trigger matching

Upstream descriptions are written for their own router. Rewrite to the concrete vocabulary a request will actually contain — model lines, error strings, protocol names, and the user's own language. A description in English will not match when the user asks in Portuguese.

## Do not paste credentials into example commands

Upstream examples routinely hardcode `-u admin:senha`. Convert them to environment variables (`-u "$DEV_USER:$DEV_PASS"`) before installing, so the pattern that gets copied is the safe one.
